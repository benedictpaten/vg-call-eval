# Where the structural-variant gap against PanGenie actually is

Generated by `scripts/wgs/sv_delta.py` from `work/wgs-mm095/score` and `work/pangenie/score`. Autosomes only, SVs
of 50 bp up to truvari's default 50 kb size cap, truth T2T-Q100 v1.1 (GIAB defrabb V0.019
draft benchmark). The `10000+` size band therefore ends below 50 kb.

## The gap as truvari scores it

| | TP-base | FN | TP-comp | FP | F1 |
|---|---|---|---|---|---|
| vg call | 14,163 | 9,458 | 14,015 | 12,287 | **0.5643** |
| PanGenie | 13,749 | 9,872 | 13,562 | 10,544 | **0.5722** |

Recall is over truth records (TP-base, FN) and precision over calls (TP-comp, FP), as
truvari's own F1 is; one call can match several truth records and the reverse.

Every truth row is a distinct variant keyed on (CHROM, POS, REF, ALT), so the set
arithmetic below counts the same things as the totals above.

## 1. The misses, and the part of them that is actionable

- missed by **both**: 8,222 (74.0% of all missed)
- **vg only** (PanGenie found it, so the panel carried the allele): 1,236
- **PanGenie only**: 1,650

`vg only` is the population worth working on: the allele was demonstrably available and the
read model declined it. The same inference does not run the other way from these files.

## 2. Does the advantage survive requiring the right genotype?

truvari's default match is locus, size and sequence -- **not** genotype. It records the
genotype difference as `GTMatch`, so the same comparison can be rescored with a correct
genotype required. This matters here specifically: the read model's known SV defect was a
mis-genotyping one, invisible to a genotype-blind metric.

| | TP (locus match) | of those, GT correct | TP (GT required) | F1 (GT required) |
|---|---|---|---|---|
| vg call | 14,163 | 12,840 (90.7%) | 12,840 | **0.5145** |
| PanGenie | 13,749 | 12,534 (91.2%) | 12,534 | **0.5252** |

A locus-matched call with the wrong genotype is counted as both a false positive and a
false negative under the stricter rule, which is what a genotyper getting the copy number
wrong has actually done.

### Splitting the excess by type

| | same-length substitutions | genuine INS/DEL | total |
|---|---|---|---|
| vg call | 201 | 12,086 | 12,287 |
| PanGenie | 29 | 10,515 | 10,544 |
| difference | **+172** | **+1,571** | +1,743 |

Same-length substitutions -- REF and ALT of equal length -- are a representation artefact rather than an evidence one: truvari sizes such a record by its allele length and so scores it as structural. vg's output carries them and PanGenie's essentially does not.

**vg emits 1,571 more genuine insertion and deletion false positives than PanGenie**, so the substitutions account for only 172 of the 1,743 excess and the rest is real disagreement about what is there.

Rescoring with substitutions excluded from both sides:

| | TP-base | FN | TP-comp | FP | F1 |
|---|---|---|---|---|---|
| vg call | 14,163 | 9,458 | 14,015 | 12,086 | **0.5665** |
| PanGenie | 13,749 | 9,872 | 13,562 | 10,515 | **0.5725** |

The gap falls from 0.0079 to 0.0060, so **25% of the headline SV F1 gap is this one representation artefact**.

With the substitutions excluded, the rest is precision: vg's recall is 0.5996 against PanGenie's 0.5821, and its precision 0.5370 against 0.5633.
